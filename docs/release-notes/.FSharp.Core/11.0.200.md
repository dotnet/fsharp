### Added

* Add the `GeneratedRuntimeAsyncSequenceBase.Close` and `CompleteMoveNext` compiler-services members for runtime-async sequences; `DisposeAsync` now runs pending `finally` blocks through `MoveNextAsync`. ([PR #20655](https://github.com/dotnet/fsharp/pull/20655))

### Fixed

* Correct `FSharpValue.PreComputeTuplePropertyInfo` to report that struct tuples store elements in fields, not properties, and recommend supported tuple readers instead of reporting a valid index as out of range. ([Issue #20801](https://github.com/dotnet/fsharp/issues/20801), [PR #20815](https://github.com/dotnet/fsharp/pull/20815))
* Quotation debug text from `Expr.ToString()`, `Expr.ToString(full)`, and `%A` now prints struct tuple construction as `NewStructTuple`; reference tuples remain `NewTuple`. ([Issue #20800](https://github.com/dotnet/fsharp/issues/20800), [PR #20814](https://github.com/dotnet/fsharp/pull/20814))
* Fix struct tuples in query expressions: selecting one no longer fails with "unreachable", and the items of one that a later operator reads are taken from its fields instead of failing with `ArgumentException: Struct tuples store their elements in fields, not properties`. ([Issue #15522](https://github.com/dotnet/fsharp/issues/15522), [PR #20894](https://github.com/dotnet/fsharp/pull/20894))
* Fix `let` bindings reaching LINQ providers as `Expression.Block`, which no provider translates: in lambdas handed to a provider, records and anonymous records with fields written out of order, tupled lambda parameters, struct copies such as `x.Nullable.HasValue`, and a `let` that only names a member, a sum, difference, product or quotient (by a constant) of members, or is read once now produce plain expressions. A `join` whose key one side builds as a tuple and the other side has ready-made, such as `join p in ps on ((k.KA, k.KB) = p.Pair)`, no longer fails with "Type mismatch when building 'ty'". ([Issue #11131](https://github.com/dotnet/fsharp/issues/11131), [Issue #15648](https://github.com/dotnet/fsharp/issues/15648), [Issue #11332](https://github.com/dotnet/fsharp/issues/11332), [Issue #3782](https://github.com/dotnet/fsharp/issues/3782) for records with fields out of order, [PR #20895](https://github.com/dotnet/fsharp/pull/20895))
* Fix struct tuples in query expressions and in lambdas converted to LINQ expression trees: selecting one no longer fails with "unreachable", and taking one apart no longer fails with a tuple index out of range. ([Issue #15522](https://github.com/dotnet/fsharp/issues/15522), [PR #20894](https://github.com/dotnet/fsharp/pull/20894))
